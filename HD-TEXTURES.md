# HD-текстуры: сборка и продолжение работы

Актуально на 8 октября 2026 года. Эта инструкция описывает HD-слой в репозитории
с патчами Silent Storm. Подробности формата и проверок находятся в
[технической инструкции](assets/terrain-hd/README.md), задание для новой сессии
Codex — в [CONTINUE-HD-TEXTURES.md](assets/terrain-hd/CONTINUE-HD-TEXTURES.md).

## Что хранится в Git

PNG лежат обычными файлами: оригиналы, сырые результаты генерации, нормализованные,
откалиброванные и отклонённые варианты. Также хранятся точные промпты и метаданные.
ZIP, Git LFS и скачивание из GitHub Releases не используются.

После двенадцатого пакета новых групп это 11 651 PNG, 10 364 610 669 байт до сжатия и удаления дубликатов
Git. Готовый native pack занимает ещё около 7,2 ГБ; оставьте место и для сборки
игры. Его `.res`, `manifest.json`, `validation.json` и `build-state.json`
создаются в игнорируемой папке `res-hd` и **не коммитятся**.

| Файл/каталог | Назначение |
| --- | --- |
| `assets/terrain-hd/sources.json` | Принятые изображения, размеры, альфа, калибровка, происхождение |
| `assets/terrain-hd/expanded/queue.json` | Статус каждого ресурса текущей очереди |
| `assets/terrain-hd/expanded/original/` | Проверенные декодированные исходники |
| `assets/terrain-hd/expanded/generated/` | Сырые, нормализованные и откалиброванные изображения, промпты |
| `assets/terrain-hd/expanded/full-texture-inventory.json` | 5 801 запись текстур БД; это инвентарь, а не готовая очередь генерации |
| `cmake/HDTextures.cmake` | Автоматическая сборка HD-пака вместе с Game |

Существующий пакет собирается из клона репозитория без исторических ресурсов и
лабораторных файлов. **Для новых текстур** нужны исторические исходники Nival
и релизные ресурсы для проверки совпадения. Их читают без изменений; оригинальную
установку Steam сохраняют неизменной.

## Сборка и установка

Для преобразования принятых PNG нужны **Python 3.11+ и Pillow**. Для числовой
калибровки дополнительно нужен NumPy. AI-сервис при сборке не вызывается.
Остальные зависимости игры перечислены в [README.md](README.md#сборка).

Пример для Windows из корня репозитория, после установки CMake, Visual Studio
и SDL3. `SDL3_DIR` должен указывать на каталог `cmake` пакета разработки SDL3:

```powershell
python -m venv build/hd-python
$hdPython = (Resolve-Path build/hd-python/Scripts/python.exe).Path
& $hdPython -m pip install Pillow numpy
cmake -S . -B build -A x64 "-DSDL3_DIR=$env:SDL3_DIR" "-DPython3_EXECUTABLE=$hdPython" -DS2_BUILD_HD_TEXTURES=ON
cmake --build build --config Release --target Game
& $hdPython assets/terrain-hd/validate_pack.py --pack build/Release/res-hd
```

Перед конфигурацией убедитесь, что `SDL3_DIR` задан. Если используете уже
настроенный каталог сборки, сохраните его генератор, архитектуру и остальные
параметры. Важен именно Python, указанный в `Python3_EXECUTABLE`: Pillow,
установленный в другой интерпретатор, не исправит ошибку конфигурации.

Game зависит от цели `S2HDTextures`, включённой по умолчанию. Она создаёт
`res-hd` **рядом с исполняемым файлом**. Для Windows с несколькими конфигурациями
это, например, `build/Release/res-hd` или `build/RelWithDebInfo/res-hd`.
Пакет можно собрать отдельно:

```powershell
cmake --build build --config Release --target S2HDTextures
```

Для Linux используйте платформенную конфигурацию из
[отчёта о сборках](diagnostics/MODERN-DISPLAY.md), добавив
`-DPython3_EXECUTABLE=/absolute/path/to/venv/bin/python` с установленным Pillow
и `-DS2_BUILD_HD_TEXTURES=ON`.
Далее соберите цель `Game`. В обычной конфигурации с одним вариантом сборки
пакет находится в `<каталог сборки>/res-hd`. При кросс-компиляции нужен Python
хост-системы, поскольку он выполняет преобразование на машине сборки.

При переносе сборки скопируйте **весь каталог `res-hd`**, каталог `fonts`,
Game и необходимые библиотеки. Пример размещения Windows-сборки:

```text
patched-game/
  Game.exe
  SDL3.dll
  ...остальные необходимые библиотеки...
  fonts/
  res-hd/
    Textures.res
    ...все пронумерованные .res...
    manifest.json
```

Рабочим каталогом игры должна быть отдельная копия игровых данных с `game.db`,
`cfg` и полным `res`. HD-пак сначала ищется рядом с Game, затем используется
`res-hd` рабочего каталога как запасной вариант. При отсутствии HD-ресурса
загрузчик берёт оригинал. Не копируйте HD-файлы поверх базового `res`.

### Повторная сборка

CMake использует `--incremental`: проверяет размер и время изменения входов
и всех выходных файлов. Неизменённый пакет пропускается; изменение PNG,
метаданных, маски или выходного файла, удаление shard-файла вызывает пересборку.
Это проверка состояния файлов, а не повторное хеширование всего содержимого
при каждом запуске. Для принудительной пересборки, в том числе после смены
Python/Pillow, выполните без `--incremental`:

```powershell
& $hdPython assets/terrain-hd/build_pack.py --output build/Release/res-hd
& $hdPython assets/terrain-hd/validate_pack.py --pack build/Release/res-hd
```

`-DS2_BUILD_HD_TEXTURES=OFF` отключает только шаг сборки пакета. Эта опция не
удаляет уже существующий `res-hd` и не заменяет переключатель в меню игры.

## Добавление новых текстур

1. Проверьте использование ресурса, тип, логические размеры, альфу и раскладку
   атласа. Сопоставьте декодированные исторические пиксели с релизом. Совпадение
   имени файла недостаточно; запишите SHA-256 RGBA и результат проверки.
2. Сохраните оригинальный PNG и добавьте запись `pending` в текущую очередь.
   Новые группы сначала подготовьте отдельными списками, затем согласуйте
   их с общей очередью. Не исключайте цветовые RGB565 как normal map.
3. Прочитайте установленный skill `imagegen`. Осмотрите исходник и выполните
   отдельное редактирование встроенным `image_gen` для каждой текстуры.
   Сразу сохраните сырой PNG и точный промпт; не полагайтесь на историю чата.
4. Импортируйте только новые задания. Осмотрите результат после нормализации
   и числовой коррекции приватно. Сохраняйте UV, частоту повторов, число деталей,
   отверстия, повреждения, материалы и исходный масштаб рисунка. Трава должна
   сохранять мелкий рисунок, а не превращаться в крупные листья или новые растения.
5. Выравнивайте яркость численно, затем соберите и проверьте **весь** native pack.
   Обновите покрытие и документацию только по реально принятым результатам.

Importer требует уже существующую запись очереди с `texture`, `category`, `role`,
`logical_size`, `original_png`, `source_rgba_sha256`, `alpha_extrema` и при
необходимости `layout`. Пример отдельного списка заданий `build/hd-jobs.json`
для ресурса 5076 **после** добавления и проверки его исходника:

```json
[
  {
    "id": 5076,
    "generated": "G:/SS/saved-generations/5076.png",
    "prompt": "Здесь должен быть полный точный текст фактически отправленного промпта."
  }
]
```

Путь `generated` замените на настоящий сохранённый PNG. Импорт копирует сырой
файл в репозиторий, сохраняет промпт и приводит изображение к размерам 4×:

```powershell
& $hdPython assets/terrain-hd/import_generated.py --batch build/hd-jobs.json
& $hdPython assets/terrain-hd/match_brightness.py --ids 5076
cmake --build build --config Release --target Game
& $hdPython assets/terrain-hd/validate_pack.py --pack build/Release/res-hd
```

Для нескольких новых ID перечислите их после `--ids`. Без этого аргумента
калибровка обрабатывает весь принятый набор. Она всегда начинает с одобренного
некалиброванного PNG, поэтому затемнение не накапливается. В native pack
восстанавливается исходная альфа с повышенной плотностью; коррекция учитывает
premultiplied RGB, заполняет цвет под силуэтом и убирает скрытый мусор.

`--replace` разрешён только для конкретной проверенной повторной попытки.
Не импортируйте старые целые пакеты поверх принятых исправлений. Регистрацию
`register_alpha_bbox` / `register_rgb_bbox` включайте лишь после проверки
исходного UV-положения: автоматически обрезать поля у всех изображений нельзя.
`reuse_generated.py` переиспользует результат только для `pending`-дубликатов
с одинаковыми RGBA, размерами, типом и раскладкой; совпадение имени недостаточно.

`validate_pack.py` проверяет алиасы, размеры, все mip-уровни, хеши, native-альфу
и яркость. Он записывает `validation.json` в выходной пакет **и обновляет
статусы/хеши общей очереди**. Это изменяющая метаданные операция: её, импорт,
калибровку и сборку выполняет один координатор последовательно. Сабагенты могут
готовить независимые изображения и свои списки заданий.

Подготовка исходников/новых очередей пока не оформлена единым переносимым
инструментом в репозитории. Прежние помощники в `G:/SS/lab` — локальные файлы;
не считайте их частью клона. При доработке декодера/подготовки очереди добавьте
нужный переносимый инструмент в репозиторий и зафиксируйте его команды.

## Очередность продолжения и ограничения

Десять подтверждённых цветовых RGB565-ресурсов завершены и проверены:
**5076, 5168, 5169, 6997, 7581–7586**. Подробности и проверка исходников:
[rgb565-followup.json](assets/terrain-hd/expanded/rgb565-followup.json).
Исходники повторно совпали с релизом; результат проверки и принятия находится в
`expanded/rgb565-batch-check.json`. Native MMP format 8 — `CF_R5G6B5`, обычный цветовой формат. Прежний фильтр
ошибочно исключал DB `Format=565` вместе с normal map.

Отдельные очереди персонажей/одежды, экипировки, оружия, голов/лиц,
интерфейса и эффектов подготовлены в `expanded/groups`: 1 803 совпавших с релизом
исходника и 15 отсутствующих исторических файлов. Это подготовка, а не принятое HD.
Связи ресурсов, ограничения и команды воспроизведения: `expanded/groups/README.md`.
Первыми зарегистрированы 20 осмотренных исходников этих групп; остальные требуют
осмотра UV и художественного/технического содержания перед генерацией.
Для UI отдельно проверьте физические и логические размеры,
координаты атласов и читаемость текста; векторные шрифты апскейлить не нужно.
Проверенные Bump/normal, технические и структурные карты сохраняют оригиналы.

Не заменяйте отсутствующие или несовпадающие исходники выдуманными текстурами.
Для 5864 и восьми ID с недоступной генерацией сохраняется fallback:
5930, 5932, 6732, 7110, 7112, 7113, 7117, 7118. Отказы сервиса не обходят.
Разрешённая пользователем замена рисунков обложек касается только уже завершённых
книжных текстур 3795, 3796, 3797, 3953, 6206, 6207.

Пользователю не показывают новые сравнения и не создают HTML-сравнения.
После существенного расширения проверяют HD → оригиналы → HD через настоящее
меню в изолированном запуске, сохраняют кадры и отчёт, затем штатно закрывают
свой запуск (`quit` для harness). Чужие/пользовательские процессы не закрывают.

## Коммиты, публикация и доказательства

Коммитьте PNG, точные промпты, метаданные, нужные инструменты и документацию.
Готовые `.res` и другие выходы `res-hd` в Git не добавляйте. Большие наборы
отправляйте ограниченными коммитами/пушами примерно по **500 МиБ**. Проверяйте
размер отдельного файла (держите его ниже 100 МБ), размер push и успешность
отправки. Если нужна промежуточная ветка переноса, финальные метаданные в
`develop` должны ссылаться на уже опубликованные PNG.
