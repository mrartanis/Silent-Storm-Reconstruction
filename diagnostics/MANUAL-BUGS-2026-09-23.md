# Ручной прогон Windows/x64: наблюдения 2026-09-23

Источник: пользовательский ручной запуск из изолированного
`G:\SS\lab\runs\face-native-manual-20260923-01`. Это сообщения о наблюдениях,
а не подтверждённые различия с оригинальной x86-игрой. Не менять и не
коммитить пользовательский сейв или дамп из `lab`.

## Исправлять в текущем шаге

- **Крэш в конце прогона.** Дамп и журнал от 23:10:38 показывают AV в
  `NAI::HasSame` при поиске пути для `CAIRetreatReaction::Update`. Поле цели
  реакции `pos` содержит значение конструктора по умолчанию: слой 255, тогда
  как у карты шесть слоёв. Это непосредственная причина выхода за границы;
  источник невалидной цели (скрипт, сохранение или создание реакции) пока не
  доказан. Добавлены проверка входных клеток в `GetTransitionType` и выход
  из реакции отступления с невалидной целью; требуется игровой регресс-тест.
- **Клик по «умению» не даёт эффекта — исправлено для бойца за орудием.** Различать две панели:
  руководство оригинальной игры (`Docs/manual/part6.html`, строки 320–323)
  прямо говорит, что на экране «Атрибуты и навыки» менять параметры нельзя;
  они растут от опыта. На отдельном экране «Умения» доступная иконка в дереве
  должна покупаться за очко (там же, строки 360–380). Проверить на сейве
  `game/save/default/stational weapons` Юки находилась за стационарным
  оружием и имела одно очко. Клик по доступной иконке в дереве ничего не
  менял: `CUnitStateUsingCannon::CreateExecutor` запрещал `CCmdTakePerk`.
  После допуска этой команды повторный клик на изолированной копии сейва
  выбрал «Специалист по пистолетам», уменьшил число очков с 1 до 0 и дал
  запись `Perk ... was taken` в журнале. Исходный сейв не перезаписывался.
- **Состояние стационарного пулемёта после кат-сцены — исправлено.** Персонаж
  стоял рядом с мотоциклом, хотя интерфейс предлагал действия как для сидящего.
  Сброс позы происходил ещё до ролика: при переходе в пошаговый бой
  `TBS_STOP_MOVE_AND_CANCEL_ACTION` вызывал `animator.PlaceUnit` после
  `EnterCannon`, возвращая модель на землю без изменения состояния орудия.
  Теперь этот сброс пропускается, если аниматор уже привязан к орудию.
  Пользователь подтвердил исправление.
  Сейв `stational weapons` сделан сразу после ролика; он полезен для проверки
  сохранённого состояния, но может не воспроизвести сам переход через ролик.
  Пользователь дополнительно подготовил `pre_cutscene` в
  `G:\SS\lab\runs\manual-bugs-fix-20260923-02\game\save\default`: загрузить,
  сесть в мотоцикл с MG34, дождаться кат-сцены, затем сравнить позу модели с
  игровым состоянием. Проверять только на копии этого сейва. Воспроизведение
  и кадры до/после исправления: `G:\SS\lab\runs\pre-cutscene-repro-20260923-02\evidence`.
  Временная трассировка показала `EnterCannon`, затем `PlaceUnit` из
  `CUnitServer::OnTBSEvent`; диагностический код после проверки удалён.
