# Пользовательские пути: перенос этапа 2

На 2026-09-24 добавлен платформенно-независимый `PortableUserPaths` с явной
политикой выбора абсолютного каталога пользовательских данных: Windows —
`LOCALAPPDATA/Silent Storm Reconstruction`, Linux —
`XDG_DATA_HOME/silent-storm-reconstruction` либо `HOME/.local/share/...`,
macOS — `HOME/Library/Application Support/Silent Storm Reconstruction`.
Абсолютный `S2_USER_DATA_DIR` предусмотрен для изолированных тестовых запусков.
Резолвер не зависит от текущего каталога и отклоняет относительные пути и
компоненты `.`/`..`. Имя профиля/слота проверяется отдельно: запрещены пустое
имя, компоненты обхода каталога, разделители пути и недопустимые для Windows
символы. Тест принимает имена с пробелами и кириллицей; реальная запись файла
с кириллическим именем пока не проверена.

`PortableUserPathsTests` прошёл на Windows x64 (`ctest -C RelWithDebInfo`) и
Linux x86-64 (`g++ -std=c++17 -Wall -Wextra -Werror -fsanitize=address,undefined`).
Linux-проба лежала в `/tmp/s2-userpaths.hiYMCj` на `artanis.c.ibgene.org`.

`CSaveManager` теперь использует этот корень для всех профилей, слотов и
вспомогательных файлов `temp`. Ресурсы и `game.db` остаются в каталоге игры.
При первом обращении к сейвам игра копирует старый `save\\` в новый каталог,
не удаляет и не перезаписывает исходные файлы; после успешного копирования
создаёт `.legacy-save-imported`. При сбое копирования следующий запуск
повторяет недостающие файлы, но не затирает существующие. После успешного
импорта маркер не даёт повторно возвращать из старого каталога удалённые
слоты. Имена профилей/слотов проходят проверку перед файловыми операциями;
точки повторного разбора (junction/symlink) не обходятся при импорте и
рекурсивном удалении. Каждый `Start-LabRun.ps1` передаёт игре отдельный
`S2_USER_DATA_DIR=<run>/user-data`.

Проверка до чистого архива: в `stage2-user-paths-dev-01` старый `DB_OLD`
лежал только в `game/save/default`. Игра скопировала `game.sav` и
`restart.sav` в `user-data/save/default/DB_OLD`; оба SHA-256 совпали с
оригиналами, загрузка дала `LOAD-DESERIALIZE-COMPLETE`/`LOAD-SLOT-DONE`.
Новый `S2_ROUNDTRIP` записался **только** в user-data и успешно загрузился.
После штатного выхода копия импортированного `DB_OLD` была перемещена в
`evidence/imported-db-old-after-first-run` (не удалена); при повторном
запуске `DB_OLD` не появился вновь, хотя исходный слот остался в `game/save`.
`S2_ROUNDTRIP` повторно загрузился, оба запуска завершились без crash dump.
Это dev-прогон с заменой EXE/PDB из рабочего дерева в архиве `db8b155`.

Затем из чистого коммита `ef961cc` собран архив
`G:\SS\lab\builds\stage2-user-paths-20260924-01` (`RelWithDebInfo`, x64,
NativeSFX). Чистый прогон `G:\SS\lab\runs\stage2-user-paths-clean-01` повторил
импорт старого `DB_OLD` с совпадением SHA-256 обоих файлов, успешную загрузку,
запись нового `S2_CLEAN` только в `user-data` и его повторную загрузку с обеими
метками завершения. Crash dump не создан. Эта проверка подтверждает выбранный
старый слот и цикл сохранения, не совместимость всех исторических сейвов.

Ограничения: `config.cfg` и скриншоты пока пишутся в каталог игры. Узкая
Win32/CRT-граница использует ANSI-имена файлов: путь с кириллицей требует
отдельной проверки/перевода на wide API. Переносимый резолвер проверен на
Linux x86-64 под ASan/UBSan, но вся игра по-прежнему собирается только на
Windows; ARM64 и настоящий macOS не проверены.
