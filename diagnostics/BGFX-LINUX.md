# Игра на bgfx в Linux

Linux x64 проверен 1 октября 2026 года на стенде `artanis.c.ibgene.org`
с Ubuntu 22.04. Полная игра использует SDL3 и bgfx Vulkan с программным
lavapipe. Проверены главное меню с 3D-сценой, освещённый склад, русский
интерфейс, обычный ввод F10/Escape, изменение размера окна, запись скриншота,
сохранение игрового слота и повторная загрузка. Та же полная игра собрана
для ARM64 и запущена через QEMU с ARM64-драйвером lavapipe.

## Сборка и исправления

Для полной игры включается `S2_BUILD_GAME=ON`; Linux-сборка требует Clang
с поддержкой исторических анонимных членов union. Переносимые тесты ядра
по-прежнему собираются независимо от полной игры. Исторические регистр и
обратные слеши в include исправляются в копии исходников внутри каталога
сборки. Отсутствующий файл из списка исходников останавливает конфигурацию.

Используются те же закреплённые SDL3 3.4.16, bgfx/bimg/bx, FFmpeg 8.1 и
miniaudio 0.11.25, что и в Windows. Linux читает PNG через системную libpng,
а составной GDP для нативного LifeStudio — через libgsf. Старые числовые
графические токены сохранены как данные адаптера; D3D runtime отсутствует.
Доступ к оригинальным ресурсам учитывает обратные слеши и регистр пути.

При запуске обнаружены и исправлены следующие ошибки:

- UI-текстуры вычисляли размеры до загрузки связанных текстур из `game.db`.
  Таблица текстур теперь импортируется первой, независимо от порядка
  указательного хеша. Это покрыто `NativeGameDatabaseLoadTests`.
- Linux-игра не регистрировала UI-функции Lua, необходимые сохранению.
  Полная игра регистрирует их вместе с оконными tag methods.
- Входы SPIR-V назывались `i.position` вместо ожидаемого bgfx `a_position`.
  Общий генератор шейдеров теперь передаёт имена атрибутов bgfx; проверка
  читает настоящие пиксели Vulkan и Direct3D 11.
- Локаль POSIX отбрасывала кириллицу в форматированном UI. SDL-адаптер
  выбирает `C.UTF-8` для классификации символов, сохраняя числовую локаль.
  Изменение размера окна ожидает `SDL_SyncWindow`. Отсутствующий конфиг
  больше не передаёт неинициализированный буфер парсеру команд.
- Чтение единиц размера шрифта через `%2s` заполняло wide-буфер узкими
  символами в Linux. Обработчики UIML и форматирования текста используют
  `%2ls`; пункты главного меню снова имеют ожидаемый размер и не перекрываются.
- Windows-обработчик диагностического исключения полностью исключён
  препроцессором на Linux, включая его условие. Обычный запуск без `-harness`
  теперь входит в игровой цикл; отдельно проверены меню и штатное закрытие
  окна на x64 и ARM64.

## Общая матрица

| Платформа | Результат | Графика |
| --- | --- | --- |
| Windows x64 | 176 из 177 | bgfx Direct3D 11, NVIDIA |
| Linux x64 | 147 из 147 после адресных повторных проверок | bgfx Vulkan, lavapipe |
| Linux ARM64 / QEMU | 147 из 147 | bgfx Vulkan, ARM64 lavapipe |

Linux: полный первый прогон 145 тестов занял 221 секунду. Единственный
неудачный тест `SDLPlatformInputTests` затем прошёл после синхронизации
размера окна и исправления ожидания Unicode: Windows передаёт UTF-16,
Linux с 32-битным `wchar_t` передаёт целый scalar. Все три SDL-проверки
повторены успешно. Добавленные Linux-прогоны всех 52 корней с отрядом и
с сохранением/загрузкой отряда также прошли: 186 и 205 секунд. После
исправления отсутствующего конфига повторены console/config и SDL input.

ARM64: единый полный прогон 147 тестов через QEMU занял 3091 секунду.
Построение всех 52 карт прошло с исходным digest (1621 секунда).
Все 52 мира прошли post-init (2683 секунды), вариант с отрядом
(2591 секунда) и сохранение/загрузку с возобновлением тиков отряда
(2728 секунд). Расширенные проверки выполнялись параллельно.

Windows: полный прогон 177 тестов занял 116 секунд. Единственная ошибка —
`NativeScenarioRootMaps`: все 52 карты построены, но итоговый digest
`e0a125f5245f5923ed6ba00e0b333a1353c426fee50004cab434b6eec2843d3f`
отличается от ожидаемого
`c79a9c158d3f64204b1529ae576f4b74e59388dd7f9531ad725f2994dcf3894d`.
Это то же расхождение, записанное до текущего Linux-переноса в
[LIGHTING-X64.md](LIGHTING-X64.md). Linux проходит исходный digest.
Эталон не заменён. После исправления отсутствующего конфига его Windows-тест
повторён успешно.

После исправления размера шрифта Windows-проверки графики и font wire
прошли повторно (2 из 2); Linux x64 Vulkan и SDL input также прошли
повторно (2 из 2). Обе Linux-архитектуры проверены визуально на финальных
бинарниках: главное меню 800×600, один и тот же освещённый склад, F10/Escape
и изменение окна до 1024×768. Финальные кадры склада x64 и ARM64 визуально
согласуются; это живые кадры в разное время, не побитовое сравнение сцены.
Слот `arm64_vulkan_roundtrip`, записанный полной ARM64-игрой, также успешно
загружен и отрисован в Windows x64.

`BgfxRendererTests` на обеих платформах проверяет depth, порядок проходов,
render targets, texel upload, stencil 0x80/0x40, blending/alpha test,
cube sampling, readback, resize и освобождение. Это адресные GPU-регрессии;
они не доказывают полный визуальный паритет со Steam. Живые кадры освещения
сопоставлялись с уже проверенным Windows-сохранением. Оригинальный Steam EXE
остаётся эталоном поведения согласно [BGFX-WINDOWS.md](BGFX-WINDOWS.md).

## Доказательства и воспроизведение

Стенд: `/tmp/s2-stage4-linux-20261001`, сборка `build-x64-clang18`.
Финальные запуски `runs/x64-vulkan-release-final-02` и
`runs/arm64-vulkan-release-final-02` содержат отдельные бинарники,
пользовательский каталог, меню и кадр после загрузки Linux-сохранения.
Запуски `runs/x64-vulkan-normal-final` и `runs/arm64-vulkan-normal-final`
проверяют обычный запуск без harness на тех же финальных бинарниках.
Предыдущий `runs/x64-vulkan-05` содержит запись слота
`linux_vulkan_roundtrip`, его повторную загрузку и кадр 1024×768.
Артефакты собраны локально в
`G:\SS\lab\builds\stage4-linux-x64-vulkan-20261001-02` и
`G:\SS\lab\builds\stage4-linux-arm64-vulkan-20261001-01`.

Окно создаётся в Xvfb. Для Vulkan задан
`VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/lvp_icd.x86_64.json`;
выбран программный GPU с названием `llvmpipe`, соответствующий lavapipe.
Физический Linux GPU этим прогоном не проверен.

После прогона сверены 2448 файлов на стенде с исходным SHA-256 манифестом:
2447 ресурсов и `game.db`, изменений нет. Все 2421 loose-файла игры
присутствуют. Четыре редакторских файла из Windows baseline на стенд не
переносились: `A5GAME_Data.MDF`, `A5GAME_Log.LDF`, `editor.bmp`,
`ScriptKeywords.txt`; отсутствие отмечено в `resources-check.json`.
Ресурсы, сохранения и изображения не включаются в Git.

ARM64 использует отдельный sysroot в `arm64/sysroot` на этом же стенде;
пакеты хостовой системы не заменяются. Полная игра, SDL3, FFmpeg и Vulkan
драйвер имеют архитектуру AArch64. При извлечении ARM-пакетов абсолютные
symlink преобразуются в относительные внутри sysroot, чтобы линкер не
подхватывал библиотеки хоста. В репозитории добавлен
`cmake/Toolchains/LinuxArm64Clang.cmake` с параметрами `S2_ARM64_SYSROOT` и
`S2_ARM64_GCC_TOOLCHAIN`; его свежая конфигурация и два теста ядра проверены.
`S2_BGFX_SHADERC` позволяет использовать закреплённый компилятор шейдеров
хоста при кросс-сборке. Прогоны ARM64 здесь выполняются через QEMU;
поддержка физического ARM GPU пока не заявляется.

В архивах сохранены исходники, бинарник, SHA-256, параметры конфигурации,
скрипты подготовки ARM-зависимостей, журналы тестов и визуальные кадры.
Оригинальные ресурсы подключаются отдельно. Для x64 заданы SDL3/FFmpeg
из `/tmp/s2-portable.BUy2BD`; для ARM64 — их отдельные установки в
`arm64/sysroot/opt/s2`. Тестам передан полный ресурсный каталог,
`game.db`, оригинальные Lua-скрипты и игровой каталог с `cfg/input.cfg`.
