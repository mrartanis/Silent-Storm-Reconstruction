# Курсор и частота кадров

## Найдено до изменения

`Main/Cursor.cpp` рисует изображение курсора через `CImageDraw` внутри
`CInterface::Draw`. `CCursor::Update` интегрирует накопленные относительные
`cursor_x/y` один раз за игровое обновление. `Game/Main.cpp` вызывает
`PumpEvents`, `PumpMessages` и `StepApp` последовательно в одном цикле.
Поэтому новый видимый указатель появляется только вместе с новым кадром.

`ui_hwcursor` зарегистрирован и сохраняется, но его значение больше нигде
не читается. Галочка сейчас не включает аппаратный режим. Исторический
комментарий в Cursor.cpp про flag-only path описывает реконструированную
заглушку, а не полную реализацию Steam.

`S2Platform::CaptureMouse(true)` объединяет grab, capture, relative mode
и скрытие системного курсора. `SDLInput.cpp` включает этот набор при фокусе.
Для системного указателя надо разделить удержание мыши в окне и relative mode.

Клики тоже требуют изменения: `CInterface::ProcessEvent` берёт `GetPos`,
а `UpdateCursor` выполняется позже в `CMission::InternalStep`. `SMessage`
не несёт координаты события, хотя исходный SDL mouse-button event их содержит.
При обработке пачки событий нельзя подставлять единственную последнюю позицию
мыши под все клики; надо сохранить координату и timestamp конкретного клика.
Игровой trace/выбор цели также должен использовать соответствующую позицию.

## Что делает оригинальная Steam-игра

Исследована только чтением изолированная копия
`D:/SS-lab/steam-ui-oracle-01/game/Game.exe`. Хеш и результаты сохранены в
`G:/SS/lab/evidence/cursor-research-20261003-01/audit.json`.

В этом EXE флаг имеет VA `0x98eb50`: проверка в `0x4d67f9` выбирает отдельную
ветку Draw. Аппаратная ветка получает cached cursor resource и вызывает
wrapper `0x409640`; его thunk `0xa6d1a6` вызывает Win32 `SetCursor`
через IAT `0x8b2254`. Включение/скрытие проходит через `ShowCursor`.
Загрузчик ресурса читает `CUICursor::szFileName` и имеет путь к
`LoadCursorFromFileA`. Это системный курсор с игровым изображением.

В baseline есть 25 различных `.cur` в `res/Cursors`: движение, атаки,
перезарядка, диалог, лечение, части тела и действия. Каждый содержит две
32x32 версии с hotspot. Записи CUICursor уже имеют FileName и HWCenterX/Y.
Файлы/операции не изменялись; оригинальная игра не запускалась.

## Предлагаемая реализация

1. Сделать `ui_hwcursor` рабочим, предпочитать системный режим по умолчанию
   с резервным программным режимом. Через `SDL_CreateColorCursor/SDL_SetCursor`
   передавать картинку и hotspot системе; кэшировать по cursor ID и масштабу,
   менять handle только при смене картинки/масштаба. Использовать доступные
   `.cur` либо нынешнюю UI-текстуру, чтобы сохранить рисунок и размер.
   SDL требует создания/переключения на главном потоке. GPU cursor-plane
   selection остаётся решением ОС; гарантия конкретного аппаратного plane
   не нужна для отделения от игрового Present.
2. Для обычного указателя использовать абсолютную позицию в drawable pixels,
   учитывать window-to-pixel и UI scaling. Для кнопок сохранять координаты
   конкретного SDL события до UI/world dispatch. Существующее ускорение
   относительных deltas не применять повторно к системному указателю.
3. Relative mode оставлять для удерживаемых RMB/MMB при вращении/перемещении
   камеры, с восстановлением позиции/картинки при отпускании. Проверить
   edge scroll, drag/drop, фокус, Alt+Tab, fullscreen и смену DPI.

Пиктограмма будет двигаться независимо от FPS игры. Пересчёт цели, подсветка,
AP/ToHit и реакция мира продолжают выполняться на игровых обновлениях.
Обычная подпись рядом с курсором тоже рисуется в кадре и может отставать от
пиктограммы; её можно позднее включить в кэшируемую картинку системного
курсора, если это заметно. Нельзя обещать независимость всей игровой реакции.

Отдельный поток, который только читает мышь, не ускоряет пиктограмму,
оставшуюся в framebuffer. Полное разделение UI/render threads существенно
шире этой задачи и не требуется для движения системного курсора.

## Проверка реализации

- При искусственных 20/40/120 FPS и редком Present указатель должен
  продолжать двигаться; проверить это внешним захватом экрана или камерой.
  Внутриигровой screenshot системный cursor overlay обычно не включает.
- В очереди `move -> click -> move` клик попадает в первую позицию;
  проверить обычный/двойной клик и drag/drop.
- Курсор соответствует состоянию, hotspot и масштабу, нет двух изображений;
  camera drag не упирается в край, edge scroll работает.
- После загрузки сейва, смены меню, DPI и Alt+Tab нет устаревшего handle,
  неверного hidden/capture состояния или лишнего warp.

## Реализация и результат

Системный режим реализован через SDL color cursors. Использованы те же UI-текстуры,
что у программного курсора: BGRA MMP читается через ресурсный загрузчик, разворачивается
по вертикали, обрезается до DB-размеров текстуры и масштабируется до drawable/UI pixels.
Курсоры кэшируются по ID, размеру и hotspot; при стабильном изображении новый handle
не создаётся. При ошибке загрузки/создания остаётся программное изображение.
`ui_hwcursor` теперь управляет режимом; новый default — 1, прежний режим доступен
через существующую галочку. Preview boot config включает системный курсор явно,
поскольку в старых пользовательских настройках сохранялась нерабочая галочка = 0.

SDL mouse events несут абсолютную позицию конкретного события и его исходное время.
UI обновляет положение и hover перед dispatch клика. Мировой trace/action target
обновляется перед необработанным UI левым кликом; временное состояние выделения
при этом не заменяется. Для RMB/MMB в сцене применяется relative mode с фиксацией
логической позиции и восстановлением указателя при отпускании. Потеря фокуса
снимает drag/capture и отпускает все кнопки. Лишние absolute events не создаются,
если соответствующая позиция уже передана с целочисленными axis deltas.

`SDLPlatformInputTests` проверяет custom alpha image/hotspot, повторное использование
и смену масштаба, дробное absolute motion, отдельные координаты down/up в очереди
после задержки 55 ms, сохранение времени событий, relative camera axes, два удерживаемых
camera buttons, отпускание/потерю фокуса, возврат software mode и очистку при restart.
Все проверки пройдены. Также прошли `BgfxRendererTests` и `SpecularProjectionRuntimeTests`.

Игровая проверка выполнена через `ProfileFrames.py` и `CursorSmokePlan.json` на копии
`car_glints_quick_20261003`: меню, загрузка, 100/150% scale, оба режима, сохранение и
повторная загрузка, возврат в меню. Native cursor IDs 2/3/5 созданы без software fallback;
повторный выбор использует кэш. BMP системных изображений выгружены при создании
через opt-in `S2_DIAG_CURSOR_DIR` и проверены визуально (orientation, alpha, size).
Команда harness `cursorstatus` печатает mode/visibility/drag/ID/size/hotspot/cache.

Сборка и доказательства: `G:/SS/lab/runs/cursor-native-20261003-01`.
Запуск: `Play.cmd`; использует прежний основной каталог сохранений.
Тестовые процессы завершены через `quit`. Ранний smoke plan с командами без
`console` не использован как подтверждение переключений; актуальный полный прогон
сохранён в `evidence/CursorSmokePlan-observations.json`, точный EXE hash — в metadata.

Автопроверка очереди при задержке кадра не является видеозамером движения
курсора на мониторе при 20 FPS. Плавность системного overlay требует проверки пользователем
в обычном запуске. Подпись AP/ToHit, смена формы по объекту и реакция мира продолжают
обновляться на игровых кадрах; независимым от Present стало перемещение пиктограммы.

Документация: [SDL mouse](https://wiki.libsdl.org/SDL3/CategoryMouse),
[color cursor](https://wiki.libsdl.org/SDL3/SDL_CreateColorCursor),
[relative mode](https://wiki.libsdl.org/SDL3/SDL_SetWindowRelativeMouseMode).
Сверено с локальными заголовками используемого SDL 3.4.16.
