# Игровые raw-типы сериализатора: аудит этапа 2

В `CStructureSaver` переносимые кодеки уже пишут известные игровые поля
без зависимости от host-выравнивания. Для оставшихся `DataScalarChunk` и
`DataArrayChunk` с `kPortable=false` добавлен диагностический счётчик
реально прочитанных типов, их `sizeof(T)`, tag и ID внешнего объекта.
Он работает только при `g_bWireAudit` (загрузка через `-loadslot` или
`S2_WORLD_WIRE_AUDIT=1` в диагностическом world-probe),
дописывает строки `RAW-TYPE` и `RAW-TYPE-AUDIT-DONE` в `_wireaudit.log`.
Обычный игровой запуск не пишет этот журнал. Этот счётчик не охватывает
ручной `AddRawData(void*)`, поэтому не является полным статическим аудитом.

Чистый x64-архив с native media из `7843985`:
`C:\SS-lab\builds\stage2-raw-audit-20260925-01`. В изолированном запуске
`C:\SS-lab\runs\stage2-raw-audit-clean-01` установлен `-loadslot` и
скопирован без изменения старый слот `stational weapons`. Загрузка
достигла `LOAD-DESERIALIZE-COMPLETE` и `LOAD-SLOT-DONE`, затем `quit`
завершил Game/CDB без crash dump. Аудит охватил и подгрузку ресурсов при
старте, и миссионный сейв: поэтому повторяющиеся блоки журнала — разные
проходы сериализатора, а не кратность полей одного save-файла.

В этом сценарии обнаружено 54 различных имени raw-типа. Среди значимых
для игровой логики: `SRandomSeed` (9 путей типа/поля), `NAI::SPathPlace`,
`NAI::SJunction`, `NAI::SZone`, `NRPG::SCritical`, `NWorld::SObjectPlace`;
есть также геометрия, анимация, шрифты и UI. Число 54 **не** означает,
что все эти типы уже перенесены, и не доказывает полноту для других
миссий или всех оригинальных ресурсов. Следующий игровой перенос —
`SRandomSeed`: одно 32-битное слово, используемое в детерминированных
правилах и сохранениях.

Воспроизведение на этом стенде: собрать чистый архив через `Build-Lab.ps1`,
создать `New-LabRun.ps1`, скопировать слот в
`<run>/user-data/save/default/stational weapons`, записать имя в
`<run>/game/_loadslot.txt`, запустить `Start-LabRun.ps1 -GameArguments
'-windowed -800 -harness -loadslot'`. Проверить `_saveload.log`,
`_wireaudit.log` и отсутствие `evidence/crash.dmp`. Для новых типов
повторять аудит на иных миссиях и игровых действиях; не переносить
редакторские типы только потому, что они есть в исходниках.

Если не хватает места для повторного копирования 2,45 ГБ `res`,
`New-LabRun.ps1 -LinkResources` исключает `res` из копирования и
создаёт в новом LabRun NTFS-junction на проверенный
`<LabRoot>/baseline/res`. Архив EXE, `game.db`, конфиг, журналы и
`user-data` остаются отдельными. Режим годится только для чтения
неизменяемых ресурсов: не применять его к сценариям, которые меняют
ресурсы или проверяют изоляцию модов. `evidence/run.json` записывает
`LinkedResources` и точный `ResourceSource`.

Продолжение 2026-09-25: после переносов из
`PORTABLE-RENDER-STATE-WIRE.md` прежняя миссия дала ноль raw-путей,
но `pre_cutscene` и `AI_CTRL` выявили два других игровых типа —
`NGScene::TKey<CVec3>` и `NGScene::TKey<float>` анимированного света.
После их переноса чистый архив из `PORTABLE-LIGHT-KEY-WIRE.md`
загрузил `pre_cutscene` и `MID_AI` с нулевым полным raw-аудитом.
Это расширенная выборка сейвов, не глобальное доказательство нуля:
проверка каждой другой миссии и отдельных загрузчиков ресурсов остаётся
отдельной работой. Статический поиск по текущим `*.h`/`*.cpp` не нашёл
вызовов `AddRawData(` вне определения самого метода, но эта проверка
не заменяет аудит иных прямых путей записи и бинарных ресурсов.

Дополнительная выборка 2026-09-28 выполнена на чистом native-media x64

Оба дошли до `LOAD-SLOT-DONE`, каждый проход выдал

или загрузку этих старых GUI-сейвов на Linux/ARM64.

Проверка всех 52 активных корней сценариев 2026-09-28 использует
`RunScenarioRootWorlds.cmake` с `PARTY_SAVE_MODE=ON` и
`WIRE_AUDIT_MODE=ON`: каждый корень создаёт партию, сохраняет мир, читает
собственный сейв и продолжает тики. Скрипт требует ноль `RAW-TYPE` и
завершённые маркеры аудита. Единственное допускаемое расхождение —
известное чтение отсутствующего необязательного тега 1 у
`COcTreeNode` версии 1.2; его границу задаёт тег 21. Временные Lua-скрипты
для чтения мира копируются в изолированный каталог каждого корня.

На первом полном Windows-проходе оставались игровые raw-поля
`CPathInterpolator::SPathPoint`, `CNodesLayer::SLadderTransition`,
`CLayersGroup::SIgnoreRect` и `CTRect<unsigned char>`. Для них добавлены
явные байтовые кодеки и проверки размера/смещений. Повторный строгий
Windows-проход прошёл 52/52 корня с нулём raw-типов. Ложное сообщение
`UNREAD` после `CUnitStateDeath` на корне 6213 оказалось телом следующего
невалидного tombstone-объекта `0xFFFFFFFF`: диагностический проход теперь
корректно пропускает его тело, не приписывая поля предыдущему объекту.
`PortableStructureProbe --type 0x01822166` и `--invalid-bodies` помогают
разбирать такие случаи, не меняя игровой файл.

На Linux Clang/ASan/UBSan корень 3829 дополнительно выявил старое
неопределённое преобразование прочности здания `635` из float в `BYTE`.
Теперь младший байт вычисляется явно (`635 → 123`), то есть сохраняется
исходная байтовая семантика без зависимости от компилятора. После правки
тот же корень прошёл строгий аудит Clang с чтением сейва. Это проверки
сериализации и игровой инициализации, а не подтверждение графического
запуска Linux-клиента или покрытия всех возможных состояний.
ARM64/QEMU под ASan/UBSan также прошёл три адресных теста кодеков и
строгий save/load-аудит корня 3829; LeakSanitizer для QEMU отключён,
поскольку его ptrace-механизм в эмуляторе не работает.
Linux GCC x86-64 под ASan/UBSan/LSan прошёл строгий аудит всех 52/52
корней: в каждом собственный save/load и продолжение тиков, ноль
raw-типов и ноль неожиданных wire-расхождений.
Полные обычные тесты после пакета: Windows x64 Release 158/158,
Linux GCC x86-64 под ASan/UBSan/LSan 129/129.
