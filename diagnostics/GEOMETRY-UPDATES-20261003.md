# Быстрый обход индексов и частичные записи геометрии

Реализовано 2026-10-03 поверх `4b5ca1b`. Оба изменения включены по умолчанию.
Исследовательский отчёт: `ZOOM-PROFILING-20261003.md`.
Рабочее дерево не закоммичено; проверенный Game.exe и PDB сохранены в
`G:/SS/lab/runs/geometry-partial-20261003-01/game`.

## Обход индексов

`Main/IndexBounds.h` содержит отдельные циклы для uint16/uint32. Загрузки имеют
фиксированный размер, сохраняют поддержку невыровненных данных и не нарушают
aliasing. Отрицательный base vertex и переполнение проверяются по минимуму и
максимуму в int64; нормализованный массив строится только для fallback-пути.
Проверки размеров буферов в renderer сохранены.

`S2_GEOMETRY_SLOW_INDEX_SCAN=1` возвращает старый обход для сравнения.
Старый экспериментальный `S2_PERF_FAST_INDEX_SCAN` больше не требуется.
Эксперимент фиксированных tuple memcpy удалён: устойчивого выигрыша он не дал.

## Частичное обновление

Для LT_NONE используется сохраняемый общий пул геометрии. Статические и
динамические сборки разделены; геометрия сохраняет слот между кадрами.
Готовые данные каждого part сравниваются с сохранёнными байтами. Неизменившаяся
часть не копируется и не помечает GPU-блоки изменёнными; изменившаяся записывает
только свой диапазон. GPU упаковывает/загружает затронутые блоки по 128 вершин.
Перемещение, анимация, перестановка частей и изменение размера определяются
содержимым, без предположения, что TT_SIMPLE означает неподвижный объект.

При нехватке места добавляется общий банк вместо вытеснения геометрии, уже
собранной для текущего кадра. После смены видеорежима слоты инвалидируются и
восстанавливаются из part cache. Существующий механизм snapshot сохраняет
ранние draw при последующей записи в тот же диапазон в одном кадре.
В low-RAM режиме сохранён прежний путь.

`S2_GEOMETRY_FULL_REBUILD=1` отключает частичные записи для сравнения.
CSV дополнен `partial_copied_bytes` и `partial_skipped_bytes`.
Отдельные буферы на каждый combiner испытаны и заменены общими пулами после
замера стоимости дополнительных переключений потоков.

## Измерения

Один EXE, три отдельных процесса, по 300 кадров в трёх одинаковых позициях.
Сейв `stage6_entered_mission_fixture`, 2560×1440, FXAA=1, anisotropy=16,
shadows/specular/blur=1, VSync=0, анимация активна. Компиляция и GPU tests с
замерами не совмещались. SHA и flags проверены в `evidence/geometry-comparison.json`.

| Положение | До изменений | Только индексы | Индексы + частичные записи |
|---|---:|---:|---:|
| Сильное отдаление, rod=80 | 46.58 FPS | 61.72 FPS | 61.97 FPS |
| rod=50 | 63.60 FPS | 85.17 FPS | 84.97 FPS |
| Дома, rod=50 | 50.38 FPS | 64.19 FPS | 64.72 FPS |

Итоговая сборка повторно дала 62.23 / 84.80 / 65.93 FPS. Первый EXE в таблице
сохранён в `evidence/comparison-build`; итоговый отличается проверкой размера
пула и отключением подробной печати parts, теперь включаемой через
`S2_PERF_PART_TYPES=1`. Начальный замер после одного шага сохранён отдельно:
63.01 / 85.82 / 65.95 FPS.

Основной подтверждённый прирост — индексы: стоимость обхода упала примерно
с 5.3 до 0.6 мс. Частичные записи на этом сейве дополнительного устойчивого
прироста не дали. На сильном отдалении копируется около 1.24 MB данных parts
за кадр, пропускается только около 12 KB: почти всё действительно меняется.
В GPU regression неизменившиеся parts дают ровно ноль упаковок и VB uploads.
Эту проверку нельзя считать обещанием ускорения на всех картах.

## Проверки и ограничения

- IndexBoundsBench: 300 parity cases, 16/32-bit, unaligned, signed base,
  overflow и normalized output; 16-bit microbenchmark 11.75×, 32-bit 3.49×.
- VertexPackingBench: byte equality четырёх форматов.
- BgfxRendererTests: основной renderer, `--geometry`, `--partial`, `--passes`,
  `--graphics`, `--display`; все прошли. Частичные записи проверены по пикселям,
  нулевым uploads, изменённому диапазону, вращению кадров, same-frame overwrite,
  shrink/grow/format, resize/device epoch и переполнению общего пула без
  вытеснения живой геометрии. Тест зарегистрирован в CTest.
- Финальный harness: 900 кадров в исходных трёх позициях, ещё 900 кадров с
  24 pan/zoom командами (rod=60..130), смена 2K→1080p→2K, save/load roundtrip,
  120+180 кадров после переходов и screenshots. Штатный `quit`, exit code=0.

Пулы требуют дополнительной CPU/GPU памяти. Начальные банки рассчитаны на
100000 динамических или 500000 статических вершин с округлением Fibonacci;
при пиковом заполнении добавляются банки. Они освобождаются при смене режима
и завершении renderer. Другие карты, длительное исследование разных областей
и пиковое потребление памяти на них пока не измерялись.
