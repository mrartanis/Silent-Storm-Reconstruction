## Этап 0.4 — контракты данных

В `CDBTableDataStorage` добавлена внешняя диагностика схемы без изменения его подтверждённого размера 136 байт. При загрузке теперь проверяются ширины и число строк колонок, неизвестные type ID, неразрешённые ссылки и все колонки, которые ни один `Import()` не потребил. Неразрешённые ссылки агрегируются по полю и целевой таблице, поэтому ошибка объяснима и не теряется среди тысяч одинаковых строк.

Формат диагностики неразрешённых ссылок уточнён после проверки на реальной базе: прежнее поле `first-record` фактически содержало отсутствующий целевой ID. Теперь сообщение явно содержит исходные table/record, имя поля и целевые table/record, например `source-table=0x22 source-record=4 field=VariantID target-table=0x5 target-record=478`. Это позволяет воспроизвести конкретную повреждённую или намеренно висячую ссылку, не принимая target ID за запись-источник. Добавлена и обратная проверка `DB-SCHEMA MISSING`: она агрегирует поля, которые запросил runtime `Import()`, но которых нет в схеме таблицы, с типом и первой исходной записью.

Восстановлены подтверждённые поля релизной Steam `game.db`: `BackstabMeleeMult`; параметры подготовки/handling/melee оружия; `BurstStartSoundID`; FOV игровых камер предметов; roll/FOV камер FaceGen и портретов; `RequiredPerkID`; параметры Panzerklein; `CGun.MinClearDistance` и координаты `AttackOrigin`; `CSide.UIKIAPaperID`; `RPGClips4Pers.DifficultyID`. Последние два особенно важны для реконструированного колонного загрузчика: без явного импорта KIA-панель оставалась пустой, а выдача патронов игнорировала ограничение сложности.

Двусторонняя проверка обнаружила устаревший январский хвост в `CRPGWeapon`: реконструкция сохраняла `pAmmo` и запрашивала отсутствующий во всех 105 записях `RPGWeapons` столбец `AmmoTypeID`. В официальном PDB между `pWeaponType` и `pItem` нет `pAmmo`, а релизный `Import()` также не делает такого запроса; боеприпас приходит через загруженный `CRPGClip`. Поле и импорт удалены, восстановлены релизные относительные смещения хвоста структуры (абсолютные смещения после `szAnimName` в современной сборке отличаются из-за 24-байтового `std::string` вместо 12-байтового `nstl::string` релиза).

По официальным `RussianGold/EnglishGold Game.pdb` восстановлен релизный контракт формы: `SRPGSlot` содержит четыре приоритета подтипов, `CRPGUniform` имеет размер `0xB4`, импорт читает 36 колонок `ST<Place>0..3`, а `GetItemsBindPlaces` делает четыре прохода и не заполняет одно визуальное место/предмет повторно. Поля `Model2`/`ModelActive2` отсутствуют в релизных `CRPGItem` и `CRPGItem2Uniform`; это редакторские колонки, поэтому они намеренно остаются в отчёте, а не добавляются в runtime-структуры без потребителя.

Восстановлены релизные ссылки на скрипты карт. `CGlobalMap` теперь содержит `pScript` по смещению `0x10`, импортирует `ScriptID` и сериализует его тегом 2; последующие теги сдвинуты до релизных 3–6. `CChapterMap` содержит `pScript` по `0x1c`, импортирует `ScriptID` и использует релизные теги 3–5. Размеры Win32 совпали с PDB: `0x24` и `0x28`. При повторном импорте главы очищается список зон, чтобы связи не дублировались.

Так же классифицированы `Spots.SoundStepID` и `Spots.AISoundType`: релизный PDB показывает `CSpot` размером `0x18` только с `pMaterial` и `pArmor`, а релизный `CSpot::Import` читает ровно эти два поля. Звуковые колонки принадлежат редакторской схеме и не являются потерянными runtime-полями.

Дополнительная сверка layout и машинного кода отделила ещё несколько редакторских колонок. Релизный `CParticleInstance` имеет ровно массив `pTextures[48]`, а `Import()` читает `Texture0..47`; `BumpTexture0..15` и `AlphaBlending` не имеют runtime-полей. `CHead` содержит один `pMaterial` (`Material0`), поэтому `Material1..7` не следует искусственно добавлять. `CPassageObject` состоит только из `pObject` и `pUseSound`, `CUnitGroup` не имеет данных поверх `CDBRecord`, а `CNationality` не содержит `IGNationality`/`Shortcut`; соответствующие колонки `PassageZoneID`, `PassageObjectID`, `Formation`, `IGNationality` и `Shortcut` относятся к инструментам подготовки данных. Аналогично `CUIControl` релиза не содержит редакторских `Freeze`/`Text`, а `CParticle` не содержит `BumpID`.

Проверка: актуальный полный Win32 RelWithDebInfo архив `G:\SS\lab\builds\db-contract-audit-10`, изолированный прогон `G:\SS\lab\runs\db-contract-audit-run-09`, снимок `evidence\snapshot-20260922-121259`. Реальная база загружена без неизвестных таблиц, ошибок формы и отсутствующих запрошенных полей: `DB-SCHEMA ERROR=0`, `MISSING=0`; процесс штатно завершён через harness. Собранный `CRPGUniform` имеет размер `0xB4`; все 36 релизных `ST<Place>0..3`, оба `ScriptID`, `UIKIAPaperID` и непустая таблица `RPGClips4Pers.DifficultyID` потреблены. Два сообщения `DifficultyID` относятся к пустым таблицам `RPGMineDetectors` и `RPGMineDetector4Pers` (0 строк), поэтому импортёр не мог отметить их схему как использованную и живые записи не потеряны.

Ресурсный контейнер релиза также проверен на согласованном наборе: все 23 файла `res/**/*.res` имеют поддержанную v1-сигнатуру `0x96948A22` и корректное смещение заголовка внутри файла. Игра через этот загрузчик дошла до intro/menu, то есть реально открыла DB-зависимые пакеты шрифтов, текстур, звука и интерфейса; это не только проверка первых восьми байт.

**DoD 0.4 выполнен для согласованной Steam-базы.** Загрузчик читает `game.db` и 23 ресурсных пакета, знает все встреченные type ID, проверяет форму таблиц и ссылки, сообщает отсутствующие ожидаемые поля и непрочитанные колонки. Итоговый прогон имеет `DB-SCHEMA ERROR=0` и `MISSING=0`. Оставшиеся 69 агрегированных групп неразрешённых ссылок — диагностируемые несогласованности самих данных, а не молчаливые отказы загрузчика; сообщение указывает обе записи. 250 `UNCONSUMED` не скрыты: 106 из них — `UserName`, 14 — `SrcName`, крупные остальные группы относятся к редакторским метаданным и подтверждённым PDB полям без runtime-потребителя; схемы двух таблиц с 0 строк помечаются тем же механизмом, но не означают потерю живых объектов. Это закрытие не доказывает совместимость со всеми историческими модами/сохранениями и не отменяет повторную проверку контракта при добавлении новых данных.

`Build-Lab.ps1` задаёт `UCRTContentRoot` только в процессе сборки: на этой машине нативная ветка Installed Roots указывает на неверный каталог для ucrt.props. Конфигурация запускается с `--fresh`, поскольку неуспешный compiler-id оставил пустые флаги конфигураций в CMakeCache и повторная конфигурация без сброса создавала EXE без PDB. Это выявлено проверкой обязательных файлов архива. Неуспешные архивы сохранены, для запусков использовать только архив с `build.json`.

`Start-LabRun.ps1` запускает CDB с перехватом second-chance AV/C++/stack-overflow и полным дампом; обработанные first-chance исключения проходят штатно. Логи engine включает существующий `-harness`. Исключения и AI не подавляются. Для других кодов исключений требуется расширить фильтры либо сохранить остановившийся процесс; это не доказательство отсутствия других сбоев.

`Capture-Hang.ps1` делает неинвазивный снимок всех потоков и полный дамп; применим при работающем основном отладчике. Дамп сам по себе не означает зависание: сравнить два снимка и реакцию UI. В `Read-Dump.ps1` `.ecxr` для hang-дампа может сообщить отсутствие exception context — для него анализировать `~* kv`.

Системные символы автоматически из Интернета не загружаются; имена/строки нашего кода разрешаются локальными PDB. Часть системных кадров может иметь только экспортируемые имена.
